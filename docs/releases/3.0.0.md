# 3.0.0 release notes

Version 3 begins the public repository history under the Apache License 2.0.
It replaces optional ftfy repair with bounded, non-mutating encoded-Unicode
inspection enabled by default in the Python APIs, JSON traversal, CLI and
middleware. Earlier development history remains in a private archive; published
older PyPI distributions retain their original versions and licenses.

## Breaking changes

- Remove `use_ftfy` from `sanitize`, `sanitize_json`, `meter` and forwarded
  sanitizer options. Remove the CLI's `--use-ftfy` and the `[ftfy]` package extra.
  Passing the removed option raises an error; it is not silently ignored.
- Remove `ftfy_changed`, `pre_repair_report` and `pre_repair_spans` from reports.
- Encoded risky Unicode and incomplete encoded inspection now quarantine under
  default enforcement. Applications that permit educational/code examples may
  configure the two new flags explicitly.
- The project license changes to Apache-2.0. Bundled Unicode and earlier MIT
  notices remain distributed in `licenses/` and `NOTICE`.

## Migration

Use `pip install llm-input-hardening` or the remaining `[security]` extra.
Remove repair options from call sites. If ingestion needs mojibake repair,
perform that explicitly upstream, then harden the resulting text. Ensure that
later decoding cannot introduce unchecked characters.

`sanitize_and_decide("< abc&#x202E;def")` returns the same literal string, an
`IH033_ENCODED_RISKY_UNICODE` observation and a `quarantine` decision. Inspection
also covers defined Unicode escapes, percent-encoded UTF-8 and bounded nested
or mixed encodings. Ordinary `&amp;` references remain unflagged by this detector.

See [encoded-Unicode inspection](../security/encoded-unicode.md) for exact
coverage, limits, sample coordinates and enforcement configuration.
